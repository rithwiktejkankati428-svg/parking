00Executive Summary & Abstract

Abstract Metropolitan university campuses and localized enterprise environments experience chronic vehicular ingress congestion, chaotic slot hunting, and gate-access latency, severely exacerbating vehicular emissions and pedestrian safety hazards. Furthermore, the rapid adoption of Electric Vehicles (EVs) introduces specialized infrastructural contention over charging bays.

This report presents the architectural design, algorithmic formulation, and empirical evaluation of SmartPark Campus, an intelligent multi-tier distributed management system. SmartPark addresses these challenges through three fundamental innovations: (1) A Spatial Proximity & Role-Weighted Recommendation Engine utilizing Euclidean distance metrics ($D = \sqrt{\Delta x^2 + \Delta y^2}$) to optimize pedestrian transit, providing $+500$ point incentives for EVs and $+100$ point institutional guarantees for faculty; (2) A Concurrency-Safe Pessimistic Row-Level Locking Protocol running under TRANSACTION_SERIALIZABLE with SELECT ... FOR UPDATE semantics, completely eliminating Time-of-Check to Time-of-Use (TOCTOU) double-booking race conditions; and (3) A Dual-Pipeline Optical Checkpoint Automation System combining ZXing QR generation, Sarxos camera frame decimation, and autonomous daemon garbage collection (ReservationExpiryThread).
Keywords: Intelligent Transportation Systems (ITS), Spatial Optimization, Concurrency Control, Pessimistic Row Locking, Electric Vehicle Allocation, Optical QR Cryptography, Java Swing, ACID Transactions.

01Introduction & Literature Review

Modern educational campuses represent complex micro-mobility ecosystems accommodating thousands of daily commuters comprising undergraduate students, postgraduate researchers, faculty members, administrative staff, service personnel, and transient visitors. Conventional parking operations rely on uncoordinated "blind cruising" and manual pen-and-paper security gate logs. Urban transportation studies (Shoup, 2005; Arnott & Inci, 2017) demonstrate that parking search traffic accounts for 30% to 50% of localized campus congestion, resulting in substantial fuel wastage, elevated carbon emissions, and pedestrian safety hazards during peak class-change intervals (08:30–09:15 AM).

Existing cloud-dependent solutions exhibit severe operational vulnerabilities during campus wide-area network (WAN) disruptions. When internet access fluctuates, cloud systems fail to authenticate drivers at physical gates, causing immediate entrance gridlock. SmartPark overcomes these defects through a self-contained, LAN-operable, 3-tier desktop architecture with deterministic pessimistic database row locking.

02Mathematical Modeling & Spatial Recommendation Algorithm

The core intelligence of SmartPark lies in its Spatial Proximity & Role-Weighted Recommendation Engine. The campus is modeled as a two-dimensional Euclidean coordinate space $\mathbb{R}^2$. Let $\mathbf{B} = (x_b, y_b) \in \mathbb{R}^2$ represent the coordinate vector of the user's destination academic building. Let $\mathcal{S} = \{s_1, s_2, \dots, s_n\}$ represent the universe of campus parking slots, where each slot $s_i$ possesses coordinate location $\mathbf{P}_i = (x_{p_i}, y_{p_i}) \in \mathbb{R}^2$, operational status $\sigma_i$, and an electric vehicle indicator $\epsilon_i \in \{0, 1\}$.

$$D(s_i, \mathbf{B}) = \|\mathbf{P}_i - \mathbf{B}\|_2 = \sqrt{(x_{p_i} - x_b)^2 + (y_{p_i} - y_b)^2}$$
Equation 1: Euclidean Walking Distance Formulation
$$S(s_i) = S_{\text{base}} - \left( W_d \cdot \|\mathbf{P}_i - \mathbf{B}\|_2 \right) + \beta_{EV} \cdot \mathbb{I}_{EV}(v, s_i) + \beta_{Role} \cdot \mathbb{I}_{Faculty}(u)$$
Equation 2: Multi-Objective Candidate Scoring Function

Where the constant parameters and indicators are established as:

  • $S_{\text{base}} = 1000.0$: Normalized base score anchor.
  • $W_d = 10.0$: Distance decay penalty weighting factor per coordinate unit.
  • $\beta_{EV} = 500.0$: Incentive bonus granted when an Electric Vehicle ($v = \text{EV}$) evaluates an EV charging bay ($\epsilon_i = 1$).
  • $\beta_{Role} = 100.0$: Priority bonus granted to certified faculty members to guarantee convenient academic access.

033-Tier Enterprise System Architecture

SmartPark Campus adheres to a decoupled, high-performance 3-Tier Layered Architecture ensuring complete separation of concerns between user interface presentation, transactional business orchestration, and relational data persistence:

Figure 2: 3-Tier Layered Architectural Topology

Key Architectural Highlights:

  • Presentation Decoupling: The GUI layer contains zero embedded SQL strings. UI panels interact solely through high-level service contracts (e.g., reserveSlot, getRecommendedSlot).
  • Database Connection Singleton: Managed via DatabaseConnection.java, maintaining optimal connection reuse and preventing thread exhaustion under heavy desktop operations.
  • Asynchronous Daemon Operations: The background threads ReservationExpiryThread and ParkingMonitorThread execute as JVM daemons (setDaemon(true)), guaranteeing that database polling never blocks the Swing Event Dispatch Thread (EDT).

04Concurrency Control & Double-Booking Prevention

In high-throughput multi-user environments, unmanaged concurrency results in the classic Time-of-Check to Time-of-Use (TOCTOU) race condition: Thread A and Thread B simultaneously read a slot as AVAILABLE, and both subsequently issue RESERVED writes, generating an integrity collision.

SmartPark Pessimistic Locking Sequence

To ensure strict ACID guarantees, SmartPark implements a multi-step transaction protocol within ParkingService.java: 

conn.setAutoCommit(false);
conn.setTransactionIsolation(Connection.TRANSACTION_SERIALIZABLE);

// 1. Verify User does not already hold an active reservation
PreparedStatement checkUser = conn.prepareStatement(
    "SELECT id FROM reservations WHERE user_id = ? AND status = 'ACTIVE'");

// 2. Acquire Exclusive Row-Level Lock on the candidate slot
PreparedStatement lockSlot = conn.prepareStatement(
    "SELECT status FROM parking_slots WHERE id = ? FOR UPDATE");

// 3. Mutate status atomically
PreparedStatement updateSlot = conn.prepareStatement(
    "UPDATE parking_slots SET status = 'RESERVED' WHERE id = ?");

conn.commit(); // Atomically releases row lock to queued threads

Appendix: Technical Defense (Viva Voce) Invariants

Evaluation Question Core Technical Defense Answer
How does SmartPark mathematically prevent race conditions? Under TRANSACTION_SERIALIZABLE, issuing SELECT ... FOR UPDATE on parking_slots acquires an exclusive row-level X-lock. Any concurrent thread attempting to read or reserve the slot is placed in a DB lock wait state until the first transaction commits or rolls back.
Why use Euclidean distance instead of Manhattan distance? Campus pathways incorporate diagonal concourses and cross-lawn walkways between academic blocks. Euclidean $L_2 = \sqrt{\Delta x^2 + \Delta y^2}$ provides a physically superior transit approximation.
How is the Swing GUI kept responsive during webcam scanning? The video frame capture pipeline runs in an asynchronous worker thread managed by VehicleQRScannerService. Decoded results are marshaled back to the Event Dispatch Thread via SwingUtilities.invokeLater().
How does the system prevent deadlocked slot reservations? The background daemon ReservationExpiryThread queries the database every 60 seconds. Any reservation exceeding its expected arrival threshold is automatically set to EXPIRED, releasing the slot back to AVAILABLE.
